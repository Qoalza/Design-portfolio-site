## Что является оболочкой

Это одна из обсуждавшихся оболочек для будущей Admin, а не единственный формат представления проектов. Hero принадлежит Portfolio/Concept: внешний фон и сетка, header, табы сценариев, линейка ширин, viewport, штрихованная resize-зона, ручка, маркеры и их motion. Проект поставляет содержимое iframe, список сценариев и фактическую адаптивную геометрию. Внутренний HTML/CSS и брейкпоинты проекта принадлежат проекту. Подмена проекта не должна требовать ручного пересчёта CSS оболочки.

Сейчас это изолированный preview `/preview/project-responsive-hero` в `tools/concept-v2/app`. Он не встроен в страницу проекта и не подключён к Admin. Исполняемые источники текущей версии: `src/project-hero/ProjectResponsiveHero.jsx`, `ProjectResponsiveHero.module.css`, `width.mjs`, `motion.mjs`, `definition.mjs` и `src/v2/HeroTabs.jsx`/`hero-tabs.css` относительно `tools/concept-v2/app`.

## Принятое поведение iframe и управления

- Текущий начальный сценарий — Media Campaigns; текущая начальная ширина — max-width. Выбор сценарного таба мгновенно меняет `iframe.src` на соответствующую готовую сцену. Переход между сценами пока без fade/crossfade; его вариант обсуждался, но не утверждён как изменение.
- Сценарный выбор не сбрасывает выбранную ширину. Сценарии сейчас задаются массивом в `definition.mjs`; отдельной схемы данных Admin для них ещё нет.
- Iframe показывает живую адаптивную страницу. Его логическая ширина задаётся шириной просмотра, а физический размер оболочки равен **`0.6 ×` фактическому логическому размеру**. Прямой `transform: scale(.6)` применяется к контейнеру iframe; внутренние media queries получают логическую ширину. Дробная логическая ширина iframe округляется вверх менее чем на 1 CSS px, а лишнее обрезается внешним viewport, чтобы у края не возникал светлый зазор.
- Высота внешней оболочки движется вместе с шириной к высоте текущего адаптивного диапазона. Анимируемая логическая высота iframe округляется вверх до целого CSS px; clip и подложка скрывают переходный зазор. Полосы прокрутки у этого демонстрационного iframe отключены (`scrolling="no"`): при переходе Desktop → Tablet содержимое кратко выше растущего окна iframe. Это свойство оболочки, не правка внутреннего продукта.
- Клик по размерному табу запускает плавный фиксированный переход `0.5s` с ease-in-out. При ручном drag рамка мягко следует за курсором через spring; линия, ручка и рамка движутся вместе. Быстрый отпуск допускает короткую инерцию; около preset действует магнитное доведение. На min/max дальнейшее движение наружу не сдвигает рамку. При `prefers-reduced-motion` движение ширины/высоты отключается. Внутреннюю страницу отдельно не анимируем.
- Iframe не принимает pointer/focus (`pointer-events: none`, `tabIndex=-1`, `aria-hidden=true`). Resize управляется ручкой, клавишами стрелок, Home/End и табами размеров.

## Текущая геометрия Corvo, не универсальные данные

В `width.mjs` сейчас жёстко заданы логические диапазоны: Mobile `360–599`, Tablet `600–1279`, Desktop `1280–1599` и продолжение Desktop от `1600` до текущего максимума около `1933.33px`. Соответствующие физические высоты сцены: `384px` для Mobile, `660px` для Tablet, `576px` для Desktop при масштабе `0.6`. Min-width `360` и max-width `1600+` — крайние **контролы** той же шкалы, а не четвёртый и пятый адаптив продукта. Обычный подсчёт для этого проекта — **три адаптива**: Mobile, Tablet, Desktop.

Текущий максимум физической ширины `1160px`, плюс `40px` для resize-зоны, помещается в рабочую область `1200px`. Это локальная геометрия Corvo. Нельзя выводить из неё ограничения размеров других проектов.

## Требования к следующей, конфигурируемой версии

1. Один набор данных проекта должен определять список сценариев, их подписи/иконки/источники и **упорядоченный список реальных адаптивов**. Количество адаптивов переменное: один, два, три или иное поддержанное проектом число. Крайние ограничения ширины, если нужны как контролы, учитываются отдельно и не увеличивают это число.
2. Для каждого адаптива проект передаёт фактические логические границы ширины и высоту живого viewport/сцены для текущей ширины. Если высота внутри диапазона меняется, её нужно определять по реальному содержимому или явно заданному правилу проекта, а не одной высотой для всего диапазона. Размеры не заменяются условными ярлыками «Mobile/Tablet/Desktop» и не берутся из сетки текущего Hero. Границы должны быть проверены на порядок, отсутствие пересечения и определённое поведение между ними.
3. В устойчивом состоянии оболочка рассчитывает физическую ширину и высоту как `0.6 ×` соответствующий фактический логический размер. В частности, размерный preset указывает реальную ширину проекта; drag даёт промежуточную реальную ширину, которую получает iframe. Его собственная адаптивная вёрстка перестраивается на этой ширине. Во время движения оболочка плавно проходит промежуточные размеры.
4. Линейка, подписи, позиции тиков, активный диапазон, пределы drag, размеры viewport и resize-зоны строятся по входной конфигурации. Не оставлять зашитый `ADAPTIVE_LAYOUTS` из пяти элементов, сегменты `256 / 141 / 415 / 188 / 200` или пороги Corvo как общую логику.
5. При одном адаптиве линейка показывает один реальный диапазон; при двух — два. Не добавлять фиктивный Tablet/Mobile для заполнения текущего макета. Min/max могут быть показаны как отдельные крайние действия, только если для проекта заданы их фактические значения и они имеют смысл.
6. Смена проекта сохраняет chrome и принятые правила взаимодействия оболочки; его собственные сцены, размеры и число адаптивов подменяются данными проекта. Для проекта без пригодных сцен/размеров нужен явный валидируемый пустой или ошибочный state; не подставлять Corvo как fallback.

Это требования к будущей интеграции, **не утверждённая schema v3** и не изменение `ProjectDocument`/Admin. Формат хранения, импорт/публикация, выбор предельных ширин и поведение при размере `0.6 ×` больше нынешней рабочей области `1200px` по ширине или `928px` по высоте ещё требуют отдельного проектирования. В частности, нельзя молча уменьшить масштаб ниже `0.6` ради текущей рамки; сначала нужно решить компоновку внешней оболочки. Привязка к Admin затронет Shared contract и должна пройти отдельную проверку его источников и consumers.

## Критерий будущей приёмки

Для тестовых проектов с одним, двумя и тремя адаптивами: число реальных диапазонов в UI совпадает с данными проекта; все подписи и границы берутся из них; выбор preset и ручной drag передают iframe фактическую логическую ширину; измеренный внешний размер равен `0.6 ×` фактическому размеру с допуском только на субпиксельное округление; сценарии переключаются без подмены данных Corvo; motion и чистое обрезание правого/левого края сохраняются. Текущий Corvo вариант остаётся визуальным регрессионным образцом.
