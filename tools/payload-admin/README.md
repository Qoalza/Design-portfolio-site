# Des-art — локальная Payload Admin

Отдельная локальная Payload CMS. `Опубликовать` пока меняет только локальную базу.
Редизайн уже выпущен на art-des.ru из утверждённых Git-материалов; native Payload
save/reopen/export для обоих Hero проверены на временной БД. Это техническая
совместимость, а не готовое управление продакшеном. Старую Des-art Admin
не использовать как источник логики или данных.

Текущее ограничение: releaseContent редактируется техническим JSON-полем,
штатный /preview использует упрощённый прежний шаблон. Удобные поля, предпросмотр
через компоненты редизайна и отдельный release экспорт готовятся в группе 6
[активного плана](../../docs/exec-plans/redesign-production-release.md).
Личный .local не переносился и не использовался в proof или первом выпуске.

## Открыть

Из этой директории:

```sh
npm ci
npm run db:prepare
npm run dev
```

Открыть http://127.0.0.1:41740/admin и создать первого пользователя.
Email здесь используется как имя входа. Письма и восстановление пароля по почте
отключены. Для потери пароля предусмотрена локальная команда ниже. Пароль не передавать в чат.

Все данные находятся в игнорируемой `.local/`: SQLite, изображения и автоматически
созданный секрет. Каталог не входит в Git и не является резервной копией.
После перезапуска данные сохраняются. Не удалять `.local`, если в ней есть нужные
локальные материалы. На этом этапе использовать только тестовые материалы.

## Что доступно

- Стандартный русскоязычный интерфейс Payload, создание пользователя и вход.
- Проекты: название/адрес, херо, заголовок/описание, секции и галереи.
- Перестановка блоков, загрузка PNG/JPEG/WebP до 20 MB, описание изображения.
- Сохранение неполного черновика, публикация после проверки обязательных полей,
  история до 20 версий. Новый черновик не меняет опубликованную версию.
- Radix Themes подключён: стандартное уведомление на экране входа/главной —
  первый изолированный компонент. Остальные части используют готовый UI Payload.

Импорта Figma, переноса старых кейсов и отправки на
действующий сайт здесь пока нет. Модель блоков предварительная, до редизайна.

## Локальный предпросмотр

Открыть http://127.0.0.1:41740/preview в браузере с активным входом в эту CMS.
Либо сохранить проект и нажать «Предпросмотр» в редакторе. Страница показывает
сохранённый черновик; переключатель позволяет посмотреть опубликованную локальную
версию. Несохранённые изменения не отображаются: сохранить и обновить страницу.

Рендерятся заголовок, описание, херо, секции, форматированный текст, примечания
и галереи в заданном порядке. Используются копии шрифтов и базовых стилей текущего
Portfolio; это упрощённый шаблон, без device frames и сложных композиций старых
кейсов. Эти копии не обновляются автоматически при изменении Portfolio.
Данные и изображения доступны только после входа. Публичный сайт не подключён.

## Проверки и разработка

```sh
npm run generate
npm run typecheck
npm run lint
npm test
npm run build
```

`npm test` создаёт одноразовую SQLite в системной временной директории, проверяет
доступы, upload, draft/publish и порядок. Второй отдельный процесс проверяет
сохранность опубликованного проекта, черновика, версий и файла изображения
после закрытия первого процесса. Затем удаляется только fixture-база.
`npm run generate` обновляет типы и карту компонентов после изменения конфигурации.
После подготовки базы и сборки `npm start` открывает локальную собранную версию.
Обычный запуск больше не меняет схему базы автоматически. Online deployment
остаётся отдельным будущим этапом.

Собственные package-lock, Next.js, TypeScript и ESLint не используют зависимости
Portfolio. Корневые TypeScript/ESLint исключают эту директорию. Не добавлять
Payload или Radix imports в публичный App Router.

## Следующий этап

Техническая подготовка локальной CMS завершена. Следующий этап — уточнять блоки
и общие компоненты сайта/предпросмотра по редизайну. Подключение сайта к опубликованным данным и перенос реальных кейсов
требуют отдельного решения.

## Решения обсуждения 2026-09-11

- Сейчас не исправлять внешний вид пробного предпросмотра и не подключать
  настоящий шаблон сайта. Текущий шаблон принят пользователем как временная фича, а не баг.
  После редизайна несовпадение с утверждённым дизайном следует исправлять.
- Согласованный принцип будущей реализации: сайт и предпросмотр используют
  общие компоненты дизайна, различаются источником опубликованных/черновых данных.
  Это направление, а не разрешение начать подключение прямо сейчас.
- Название вкладки предпросмотра сейчас фиксированное. Использование поля
  «Название проекта» для вкладки отложено; назначение не менять до решения.

## Обслуживание и резервные копии

Перед обслуживанием остановить админку (Ctrl+C в её терминале).
Запускать сервер только через npm run dev / npm start: команды разделяют
блокировку с обслуживанием. Прямой запуск next или payload эту защиту обходит.

```sh
npm run storage -- backup
npm run storage -- list
npm run storage -- verify backup-<идентификатор>
npm run storage -- restore backup-<идентификатор> --confirm
```

Копии находятся в игнорируемой `.local-backups/`, содержат базу, изображения
и секрет входа. Они приватны: не отправлять в Git/чат/общедоступное хранилище.
Копия на том же диске защищает от ошибки редактирования, но не от потери диска.
Для отдельного носителя копировать целиком готовый каталог backup после verify.

Restore заменяет локальное состояние выбранной копией и сохраняет прежний
каталог как previous-* внутри .local-backups. Повреждённая копия не применяется.
После прерывания процесса: `npm run storage -- unlock` (только когда процессы
действительно завершились), затем `npm run storage -- recover`, если есть журнал
незаконченного восстановления. При неоднозначном состоянии команда останавливается
и сохраняет файлы. Не удалять lock/journal/previous вручную без диагностики.
Восстановление проверено для прерывания процесса; аппаратные сбои питания не
моделировались. SHA256 обнаруживает повреждение, а не доказывает авторство копии.

## Запуск и обновления базы

`npm run db:prepare` при остановленной админке готовит чистую базу либо делает
копию существующей, обновляет только staging, проверяет результат и переключает
активное состояние. Предыдущая база сохраняется. Неизвестная схема отклоняется.
Старая dev-база принимается только при точном совпадении структуры с известной
версией; на копии регистрируется её история миграций. Текущие пользовательские
данные автоматически не переводились: команда запускается отдельно владельцем.

`npm run build` создаёт сборку; `npm start` отказывается запускать устаревшую сборку
или несовместимую базу. `npm run test:smoke` запускает отдельную собранную CMS на
41741 и проверяет регистрацию, сохранение/предпросмотр, остановку и повторный вход.
Никаких личных учётных данных этот тест не использует.

Для разработчика при изменении полей: создать миграцию стандартным Payload
migrate:create на disposable fixture, проверить up/down SQL, дополнить историю
структур scripts/schema-history.json новым отпечатком, сохранив предыдущие.
Прогнать миграции на fixture с данными старой версии и npm test/test:smoke.
Тест сверяет миграции с текущей конфигурацией коллекций; забытая миграция не пройдёт.
Не запускать db push, migrate:fresh/reset/down против личной базы.

## Восстановление входа

Остановить админку и запустить `npm run account:recover` в своём локальном
терминале. Ввести email существующей записи и дважды новый пароль (12–128
символов). Ввод пароля скрыт; не передавать его в команде, через pipe или в чат.
Команда сохраняет резервную копию, меняет пароль, снимает блокировку попыток входа
и отзывает прежние сеансы и токены сброса. После запуска админки войти заново.
Новый пользователь при этом не создаётся; изменение касается указанной записи.

Этот способ предназначен владельцу локального компьютера с доступом к .local.
Он не является удалённым восстановлением и не требует почтового сервиса.
Восстановление резервной копии возвращает пароль, который был на момент копии,
но отзывает сохранённые сеансы и токены сброса: после restore нужен новый вход.

Автотест скрытого ввода на macOS использует Python 3 из окружения разработчика
для настоящего псевдотерминала. Самой админке и команде восстановления Python
не нужен; дополнительная библиотека терминала не устанавливалась.

## Защита изображений

Используемое изображение нельзя удалить, пока на него ссылается текущий кейс,
сохранённый черновик или одна из сохранённых версий. История ограничена 20 версиями.
Файл существующего изображения нельзя заменить поверх: загрузить новую картинку
и выбрать её в блоке. Описание (alt) по-прежнему можно редактировать.
Неиспользуемое изображение можно удалить обычным действием админки.

До сохранения проверяются реальные байты PNG/JPEG/WebP, полное декодирование,
лимит 20 МБ и 40 мегапикселей. Повреждённые и неподдерживаемые файлы отклоняются.
Формат и состав блоков при этом не менялись; внешний вид предпросмотра сохранён.

Все четыре этапа проверены на одноразовых базах. Личная база не восстанавливалась,
не мигрировалась и пароль владельца не менялся. Резервные операции доступны,
но автоматического расписания копий/удалённого хранения нет. Online-размещение,
подключение действующего сайта и перенос реального контента — отдельные этапы.
