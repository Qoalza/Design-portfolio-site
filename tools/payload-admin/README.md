# Des-art Payload

Онлайн-CMS и публичный сайт работают в одном Next/Payload runtime. Пользователь
открывает `/admin`, сохраняет черновик, проверяет его и нажимает штатную публикацию.
Сайт получает опубликованные данные и файлы на следующем запросе; локальный Mac,
Git, сборка и перенос контента на сервер для каждой правки не нужны.

Код этого подключения проверен на одноразовой БД и настоящем HTTP runtime.
**Установка этого варианта на VPS ещё не выполнена.** Текущий рабочий поток:
[план](../../docs/exec-plans/payload-site-integration.md),
[серверная граница](../../docs/ops/PAYLOAD.md).
Старую Des-art Admin и её данные/процесс публикации не использовать.

## Редактор

Редактируются тексты, ссылки, секции, материалы и выбранные оболочки проектов:
«Верстка» и «Фикс адаптив». Используются готовые компоненты сайта/Hero.
Главная не является конструктором. Неполные черновики допустимы; публикация
проверяет структуру, связанные файлы, размеры изображений и HTML-пакеты.
Повреждённая версия не заменяет рабочую опубликованную.

Предпросмотр показывает сохранённый черновик через заранее собранный интерфейс.
Создание доступно после входа; frame получает временный read-only адрес,
без CMS credentials. Черновики и native upload API приватны. История проектов
использует штатные версии Payload. Исходники и связанные материалы не
перезаписываются при загрузке новых файлов.

## Режимы запуска

- `server`: явные `PAYLOAD_DATA_ROOT`, `PAYLOAD_PUBLIC_URL=https://art-des.ru`,
  `PAYLOAD_PORT`; данные вне кода и публичных каталогов, сервер слушает loopback.
- `fixture`: `PAYLOAD_LOCAL_ROOT` только в одноразовом каталоге системного temp
  с префиксом `des-art-payload-test-`, порт41741.
- `development`: отдельный игнорируемый `.local`, порт41740. Личный существующий
  каталог не используется в проверках или в production bootstrap.

`npm run db:prepare` проверяет schema и применяет миграции на staging-копии;
обслуживание требует остановленного runtime. `npm run build` собирает код сайта,
private preview shell и Next. Контентные правки ничего не пересобирают.
`npm run start` проверяет текущую schema, code freshness и сохранённый secret.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
```

`npm test` принудительно использует disposable fixture независимо от входного
server environment. HTTP session checks требуют явно подготовленного fixture
и соответствующего запущенного тестового runtime; это не production smoke.
Типы и карта компонентов обновляются `npm run generate` при необходимости.

## Резервные копии и доступ

После остановки runtime: `npm run storage -- backup`, `list`, `verify <id>`.
`restore <id> --confirm` проверяет копию, сохраняет прежнее состояние и отзывает
восстановленные сессии. Живой production restore требует согласованного OPS-действия.

Email используется как имя входа. SMTP пока не подключён; восстановление пароля
через защищённую серверную консоль: `npm run account:recover`. Ввод пароля скрыт,
прежние сессии отзываются, предварительно создаётся резервная копия.
Не передавать пароль в аргументах, pipe, Git, документации или чате.
