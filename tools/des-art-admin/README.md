# Des-art Admin

Локальная админка запускается приложением `dist/Des-art Admin.app`. Приложение не устанавливается автоматически и не добавляется в автозагрузку.

При первом запуске оно создаёт отдельную управляемую копию репозитория в `~/Library/Application Support/Des-art Admin/repository`, запускает UI только на `127.0.0.1:41731` и preview на `127.0.0.1:41732`. Повторный запуск открывает уже работающую админку.

Кнопка «Завершить админку» находится внизу левой панели и останавливает API/UI и принадлежащий приложению preview-процесс. Черновики при этом сохраняются.

Интерфейс админки собирается отдельно командой `npm run admin:build` из `tools/des-art-admin/src/`. Он использует собственную границу React + Radix Themes (`blue`, `sand`, `small`) и не импортируется публичным App Router-приложением. Production-сборка проекта автоматически обновляет статический bundle админки через `prebuild`.

Для установки после пользовательского подтверждения скопировать `Des-art Admin.app` в `/Applications`. До отдельного подтверждения этого делать нельзя.

Черновики и загруженные в них изображения хранятся в `~/Library/Application Support/Des-art Admin`, поверх опубликованных данных. Каждое изменение сначала страхуется в браузере, затем атомарно сохраняется сервером. Preview компилирует валидный черновик в отдельный `preview-drafts` overlay и не пишет в `content/projects` или `public/assets`.

Preview использует отдельный Next.js build-каталог для своего порта. Поэтому одновременно работающие admin-preview и обычный dev-сервер не делят `.next`, не блокируют друг друга и не показывают старую сборку.

Интерфейс разделён на список проектов, редактор и правую панель общих настроек. Настройки примечания и интерактивного экрана находятся внутри каждой конкретной секции и сохраняются независимо. «Интерактивный экран» принимает ссылку на конкретный Figma frame, но не считается готовым и блокирует preview/publish, пока Codex не подготовит управляемый ассет. Существующие кодовые композиции отображаются read-only и сохраняются без изменений.

Кнопки публикации появляются только при наличии соответствующих неопубликованных изменений. Без `live-publish.json` админка остаётся в безопасном sandbox и обновляет только локальный snapshot. После отдельной настройки live-режима сервер сам выбирает production-поток: свежий `origin/main` → временный worktree → проверки → служебная ветка → Pull Request → merge → загрузка точного SHA на VPS → атомарный release → публичная проверка. Проектная публикация не включает порядок `/projects` и главной: эти изменения остаются до общей публикации. До запуска единая проверка показывает все проблемы на русском и ведёт к конкретному полю; невалидный черновик job не создаёт. Подробный контракт: `SPEC.md`.

Live-конфигурация и SSH-ключ находятся только в `~/Library/Application Support/Des-art Admin`, никогда не попадают в Git. Ключ ограничивается сервером командами `status`, `upload <full-sha>` и `publish <full-sha>`; shell, port forwarding и произвольные команды ему не выдаются. Тестовые каталоги `/private/tmp` не могут запускать live publish.

Новый проект создаётся по свободному названию, а уникальный URL формируется системой. Логотип необязателен и загружается вручную как безопасный квадратный SVG. Все подтверждения и сообщения об ошибках находятся внутри изолированного Radix-интерфейса; системные окна браузера не используются.

Текущий интерфейс — светлая трёхзонная рабочая область: список проектов слева, редактируемый контент в центре, состояние и контекстные настройки справа. На узких desktop-ширинах правая панель последовательно переносится под редактор. Линии и поверхности используются только для разделения самостоятельных зон и выбранной секции.
