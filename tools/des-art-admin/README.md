# Des-art Admin

Локальная админка запускается приложением `dist/Des-art Admin.app`. Приложение не устанавливается автоматически и не добавляется в автозагрузку.

При первом запуске оно создаёт отдельную управляемую копию репозитория в `~/Library/Application Support/Des-art Admin/repository`, запускает UI только на `127.0.0.1:41731` и preview на `127.0.0.1:41732`. Повторный запуск открывает уже работающую админку.

Кнопка «Завершить админку» находится внизу левой панели и останавливает API/UI и принадлежащий приложению preview-процесс. Черновики при этом сохраняются.

Интерфейс админки собирается отдельно командой `npm run admin:build` из `tools/des-art-admin/src/`. Он использует собственную границу React + Radix Themes (`blue`, `sand`, `medium`) и не импортируется публичным App Router-приложением. Обычные поля и кнопки используют системный Radix-размер `3` (`40 px`), а switches — полный радиус. Production-сборка проекта автоматически обновляет статический bundle админки через `prebuild`.

Для установки после пользовательского подтверждения скопировать `Des-art Admin.app` в `/Applications`. До отдельного подтверждения этого делать нельзя.

Черновики и загруженные в них изображения хранятся в `~/Library/Application Support/Des-art Admin`, поверх опубликованных данных. Каждое изменение сначала страхуется в браузере, затем атомарно сохраняется сервером. Preview компилирует валидный черновик в отдельный `preview-drafts` overlay и не пишет в `content/projects` или `public/assets`.

Preview использует отдельный Next.js build-каталог для своего порта. Поэтому одновременно работающие admin-preview и обычный dev-сервер не делят `.next`, не блокируют друг друга и не показывают старую сборку.

Интерфейс разделён на список проектов, редактор и правую панель общих настроек. Настройки примечания и интерактивного экрана находятся внутри каждой конкретной секции и сохраняются независимо. Обложка, главное изображение страницы и интерактивный экран принимают ссылку на конкретный Figma Frame. Корневой Frame остаётся адаптивным DOM-контейнером, а каждый его непосредственный видимый дочерний элемент сохраняется отдельным PNG-снимком `2×`. Их исходная геометрия, constraints и эффекты остаются отдельными данными композиции; все дочерние элементы не объединяются в один общий растр. Production после публикации использует локальный snapshot и от Figma не зависит. Существующие кодовые композиции отображаются read-only и сохраняются без изменений до явной замены.

Figma подключается локально из админки через Personal Access Token со scope `file_content:read`. Токен сохраняется только в macOS Keychain (`des-art-admin-figma`), не попадает в Git, JSON, browser storage, publish job или production. Импорт атомарный: неуспешная или битая ссылка не заменяет последний рабочий snapshot.

Без `live-publish.json` Admin остаётся тестовым контуром: публикация выполняет только локальную проверку. Валидный локальный `live-publish.json` формата `{ "mode": "live", "host": "…", "user": "…", "keyPath": "…" }` включает прежний live workflow: зелёный статус «Связано с art-des.ru», кнопку «Опубликовать» и окно с этапами `Проверка → Подготовка файлов → Lint, build и tests → Git и Pull Request → Merge → Deploy → Публичная проверка`. Конфигурация, ключ и их значения не попадают в Git, архивы или job-логи. До запуска проверяются baseline, GitHub CLI и ограниченный SSH status; невалидный черновик job не создаёт.

Перед первым live запуском Codex обязательно фиксирует один local request: `clean` или `overlay`, привязанный к full production SHA. Первый запуск подтверждает публичный `data-build-sha`, архивирует старый sandbox и создаёт marker v5 с отдельным live generation store. `clean` начинает с exact production; `overlay` накладывает sandbox project-authoring state в local live drafts. Ни один bootstrap не публикует данные. Последующие live-запуски сохраняют live drafts/assets/jobs.

У изменённого production-проекта рядом с публикацией появляется локальная кнопка сброса до опубликованной версии: она требует красного подтверждения и затрагивает только этот проект. Для нового draft-проекта и в sandbox кнопки нет. В памяти текущего проекта доступны до пяти текстовых отмен/повторов: `Cmd+Z` и `Shift+Cmd+Z`; загрузки, Figma, структура и action buttons в эту историю не входят.

Новый проект создаётся по свободному названию, а уникальный URL формируется системой. Логотип необязателен и загружается вручную как безопасный квадратный SVG. Preview-asset route отдаёт SVG с `image/svg+xml` и используется как карточным, так и страничным preview. Любое видимое preview открывается во внутреннем увеличенном просмотре. Все подтверждения и сообщения об ошибках находятся внутри изолированного Radix-интерфейса; системные окна браузера не используются.

Текущий интерфейс — светлая трёхзонная рабочая область: список проектов слева, редактируемый контент в центре, состояние и контекстные настройки справа. На узких desktop-ширинах правая панель последовательно переносится под редактор. Линии и поверхности используются только для разделения самостоятельных зон и выбранной секции.
