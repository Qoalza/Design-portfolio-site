# Контракт Des-art Admin

## Актуальный пользовательский контракт

- Свободное название преобразуется в уникальный slug атомарно; после создания адрес не меняется.
- Черновик может быть неполным и всегда автосохраняется. Preview и dry-run publish используют один накопительный preflight и не запускаются до исправления всех обязательных полей.
- Логотип — необязательный ручной квадратный SVG. Активная SVG-разметка отклоняется сервером; существующие составные логотипы сохраняются без преобразования.
- Настройки примечания и интерактивного экрана принадлежат конкретной секции по стабильному `adminId` и удаляются вместе с секцией.
- В левой панели только `Опубликованные / Черновики / Удалённые`; порядок меняется только у опубликованных.
- Любая публикация текущего тестового контура — dry-run: публичный сайт и production не изменяются. Успех обновляет отдельный sandbox snapshot и локальный lifecycle.

## Граница

Админка работает только локально на `127.0.0.1`, использует отдельную тему Radix и не импортируется публичным App Router. Черновики и их ассеты хранятся в `~/Library/Application Support/Des-art Admin`, а не в рабочем Git-дереве.

## Черновик и preview

- Изменение сразу страхуется в `localStorage`, затем атомарно сохраняется сервером после короткой паузы.
- Перед сменой проекта и открытием preview выполняется обязательный flush.
- Неполный черновик разрешено сохранять; preview и publish отдельно компилируют его в строгий публичный контракт и показывают русскоязычные ошибки полей.
- Preview читает отдельно скомпилированный draft overlay и env-gated draft assets; канонические JSON и публичные ассеты не перезаписываются.
- Каждый preview-порт использует собственный `.next-admin-preview-<port>`, поэтому не конфликтует с обычным dev-процессом или другим preview.

## Интерфейс и контент

- Левая панель содержит поиск и состояния `Опубликованные / Черновики / Удалённые`. Порядок можно менять только во вкладке опубликованных проектов.
- Центр содержит только вкладки `Карточка` и `Страница проекта`; контекстные настройки находятся в правой панели.
- Общая публикация и публикация проекта видны только при наличии соответствующих изменений.
- Секция содержит заголовок и одно поле описания с форматированием. Примечание включается независимо и сохраняет текст при временном отключении.
- Существующая кодовая композиция показывается read-only как «Интерактивный экран». Новая ссылка на Figma frame сохраняется как pending и блокирует preview/publish до подготовки ассета Codex.
- Галерея одна; поддерживает Desktop, Tablet и Mobile. Название и публичная подпись не редактируются.
- Все Radix-компоненты и стили принадлежат только статическому bundle админки и отсутствуют в публичном Next.js bundle.

## Публикация

Есть два scope: текущий проект и все изменения. Job хранится вне Git и работает отдельным процессом под `caffeinate`; вкладку можно закрыть, но Mac должен оставаться включённым и подключённым к интернету.

Текущая Goal включает безопасный dry-run всех этапов. Успешная публикация проекта переводит локальный черновик в `Опубликован`, записывает public-совместимый snapshot и сохраняет admin metadata только в рабочем draft. Изменения порядка `/projects` и состава/порядка главной не входят в project scope и публикуются только действием «Опубликовать все изменения». Live publish намеренно закрыт; секреты не сохраняются в job JSON, репозитории или документации.

## Доказанный пользовательский контур

- Создание принимает свободное русское название со спецсимволами и формирует системный URL.
- Slash-теги сохраняют raw-строку во время ввода и массив после blur/restart.
- Невалидный draft показывает все конкретные поля; выбор проблемы переводит на нужную вкладку и фокусирует поле.
- Card/page preview читают draft overlay; служебные file metadata не попадают в public `ProjectImage`.
- Home-limit dialog переставляет элементы, полностью отменяет изменения и применяет ровно три проекта.
- Примечание секции отключается и возвращается без потери текста; toolbar форматирует текущее выделение.
- Sandbox publish обновляет snapshot, lifecycle и dirty scope без GitHub, VPS или production.
