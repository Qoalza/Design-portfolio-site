# Design system baseline

Эта папка хранит первую репозиторную baseline-версию дизайн-системы из Figma. Снимок предназначен для проверки будущих изменений библиотеки и не заменяет сам Figma-файл.

- Baseline: `v1`
- Figma file key: `CRcI38SOIkr5knjKXeCV5h`
- Источник: https://www.figma.com/design/CRcI38SOIkr5knjKXeCV5h/My-portfolio---Library?node-id=62-4029&t=GKPd9AyK7LBg0je8-1
- Дата фиксации: `2026-08-19T21:25:06.671Z`
- Способ чтения: Figma Plugin API в режиме read-only через `figma-use`

## Содержимое

Файл `baseline.json` содержит:

- полный упорядоченный список из 11 страниц;
- 16 text styles с фактическими числовыми весами из применённых текстовых слоёв;
- 3 коллекции и 291 разрешённых variables с прямыми значениями, aliases и вычисленными цепочками;
- 13 component sets и 54 variants/components;
- component properties, variant properties, boolean/instance-swap definitions, variable bindings, используемые text styles и вложенные component relationships;
- 4 подтверждённые связи Skin → Master;
- 2 узла, роль которых нельзя канонически определить по текущей документационной структуре.

## Правило NO DEV

102 variables, чьи полные имена содержат `NO DEV`, полностью исключены. Baseline не сохраняет их имена, идентификаторы, значения, структуру или aliases. Разрешённые variables не ссылаются на исключённые.

## Master и Skin

`Master` фиксируется как источник структуры и component-property механики. `Skin` фиксируется как набор, использующий вложенный Master и задающий конкретное представление/состояния. Эти отношения документируют фактическую структуру Figma и не означают обязательное один-к-одному отображение в React.

## Канонические и неразрешённые узлы

Именованные документационные фреймы перечислены в `canonicalDocumentationFrames`. Технические, неоднозначные или находящиеся вне таких фреймов узлы записаны в `unresolvedNodes` с причиной и не интерпретируются автоматически.

## Детерминированность

JSON сформирован со стабильной сортировкой ключей и предсказуемым порядком массивов: страницы — по порядку Figma, styles и component sets — по имени и ID внутри порядка страниц, variables — по коллекции, имени и ID. Случайные или временные данные отсутствуют; изменяемым полем является только явная дата снимка.

## Обновление

Для следующей baseline-версии повторить read-only чтение всех страниц и сущностей, применить то же правило `NO DEV`, проверить alias-цепочки и сравнить новый JSON с текущим. Историю изменений для первой версии отдельно не вести.
