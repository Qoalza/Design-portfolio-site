# Web Quality Audit

Дата: 2026-08-11

## Итог

`READY_FOR_USER_REVIEW` для текущего desktop-релиза с задокументированными accessibility-исключениями.

Это технический результат аудита, а не итоговая приёмка реализации. Статус `PASSED` может присвоить только пользователь после визуального review.

## Performance

- Главная — статически пререндеренный Server Component; клиентская интерактивность и новые зависимости не добавлялись.
- Все крупные изображения подключены через `next/image` с явными размерами; hero загружается приоритетно, контентные изображения — лениво.
- Шрифты self-hosted и ограничены фактически используемыми семействами, весами и Cyrillic/Latin WOFF2-подмножествами. Общий вес шести WOFF2-файлов — около `140 KB` вместо более `4 MB` исходных TTF.
- Production-сборка не содержит ссылок на старые TTF или временные Figma URL.
- На контрольном просмотре: `23/23` изображений загружены, сломанных изображений нет, production-консоль без warning/error.

## Accessibility

- `lang="ru"`, один `h1`, последовательные `h2/h3`, все секции имеют существующие `aria-labelledby`.
- У ссылок есть доступные имена; у декоративных изображений пустой alt, у смысловых процессных иллюстраций — описательный alt.
- Добавлены skip-link и видимый `3 px` focus-ring.
- Контраст и desktop-only reflow проверены отдельно; исключения записаны в `ACCESSIBILITY_EXCEPTIONS.md`.

## SEO

- Заданы русские title и description.
- Используются семантические `header`, `nav`, `main`, `section`, `article`, `footer`.
- Ссылки и заголовки содержат текстовые доступные названия; основной контент доступен в серверном HTML.

## Best Practices

- В production-коде нет внешних временных asset URL, inline SVG, CSS-иллюстраций, сторонних UI-библиотек или `any`.
- Внешние ссылки, открывающиеся в новой вкладке, используют `rel="noreferrer"`.
- Smoke-check пройден для `/`, `/projects`, `/projects/example-project` и `/mdx-test`; найденные несовместимые HTML-комментарии в MDX заменены на корректный JSX-синтаксис.
- `npm run lint`, TypeScript и production build проходят.

## Методика и ограничение инструмента

Проверка выполнена по production-сборке в локальном Chromium: визуальный осмотр, DOM/семантика, доступные имена, alt, контраст, focus-state, загрузка ассетов, console и route smoke. Lighthouse не устанавливался, потому что его нет в проекте, а правила задачи запрещают добавлять ненужные зависимости; это не оставляет известного блокирующего дефекта, но численные Lighthouse scores не заявляются.
